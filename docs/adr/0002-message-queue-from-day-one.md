# 第一天引入外部消息队列实现跨领域事件解耦

为了确保跨业务领域（如订单提交触发审批请求生成、授信额度预占、通知推送）的高可靠性与异步解耦，我们决定从项目第一天起就强制引入外部分布式消息队列，而非依赖 JVM 进程内事件。这样可以杜绝单点内存丢失风险，强制团队在开发初期就按照分布式事务最终一致性（如配合本地消息表 Outbox 模式）与幂等消费标准进行设计，使系统天然具备向分布式微服务平滑演进的能力。

## Considered Options

- **外部消息队列（已采纳）**：强行建立进程外解耦规范，保障消息持久化与投递可靠性，未来微服务拆分零改造。
- **Spring 进程内 ApplicationEvent**：初期开发无需启动 MQ 中间件，但缺乏消息持久化与重试死信机制，未来微服务拆分时需要全部重写为 MQ 发送/消费。

## Consequences

- 本地开发与测试环境需要通过 Docker 或本地实例运行 MQ 中间件。
- 消息发送方需考虑分布式事务一致性（建议配合 Outbox 本地消息表），消费端必须实现防重复消费幂等机制。
