# 采用 RocketMQ 5.x 与本地消息表（Outbox 模式）保障分布式事务与延时消息

为了解决跨业务领域（订单、审批、授信）的分布式事务最终一致性与订单超时自动取消诉求，我们决定采用 RocketMQ 5.x 作为消息中间件，并结合本地消息表（Outbox Pattern）。在本地数据库事务中同时记录业务实体与待发事件，由可靠投递任务投递至 RocketMQ；利用 RocketMQ 原生的高性能任意精度延时消息实现订单未审批/未支付超时自动取消，彻底消除“先写库后发 MQ 导致数据不一致”的隐患。

## Considered Options

- **RocketMQ 5.x + 本地消息表 Outbox（已采纳）**：电商领域成熟度高，原生支持事务消息与任意精度延时消息，可靠性最高。
- **RabbitMQ + 延时插件**：缺乏原生事务消息机制与任意精度延时队列，依赖插件和 TTL+DLX 维护成本高。
- **Kafka**：面向流式日志与大数据，在单单延时与精细化事务反查/重试上能力不如 RocketMQ。

## Consequences

- 数据库需增加通用的 `sys_outbox_message` 表记录待投递与已投递事件。
- 消费者必须基于唯一 `event_id` 或业务单号实现幂等消费，杜绝重复消费造成的业务异常。
