# 两阶段企业审批引擎与防腐层设计

对公商城前端严格遵循 ADR 0001（订单提交后统一进入待审批，买方端不提供审批按钮）。为了避免在 MVP 阶段过早引入重型 BPMN 引擎导致数十张系统表和维护负担，我们决定采用“领域防腐层（ACL）+ 两阶段演进”方案：第一阶段在 `b2b-approval` 模块内使用轻量规则编排引擎（如 LiteFlow 或状态机）实现金额分级与单据流转；第二阶段当业务出现复杂会签、拖拽式流程设计器或对接外部 OA（企微/钉钉/泛微）时，在防腐层后平滑替换为 Flowable 7.x，对交易订单模块保持 100% 零侵入。

## Considered Options

- **防腐层 + 两阶段演进（已采纳）**：在交易域与审批域间建立清晰边界，初期敏捷轻量，后期支持无缝升级到重型工作流。
- **一步到位直接引入 Flowable 7.x**：功能全面符合 BPMN 2.0，但初期需要维护 30+ 张流程系统表，开发调试重。
- **纯数据库字段硬编码**：短期开发极快，但无法扩展多级审批、金额条件分支或外部 OA 对接。

## Consequences

- 交易域（`b2b-trade`）只依赖 `ApprovalFacade` 接口，只关心审批单号与审批状态变更事件，绝不直连审批内部数据模型。
- `b2b-approval` 模块独立维护审批单据与时间线，通过 MQ 领域事件通知订单中心推进状态。
